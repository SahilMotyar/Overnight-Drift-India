# PLAN.md

**Question.** On Indian market data, does the price path split the way the reel
says: up overnight (close -> next open), flat or down intraday (open -> close)?
And can any part of that split be traded after Indian costs?

**Not the question.** Whether the decomposition identity holds. It always does.
Night x day = buy-and-hold is arithmetic, not a finding. What matters is the
*sign and size* of each half, and whether it survives costs.

**Deliverable.** `reports/findings.md` with:
- night/day/hold curves for Nifty 50, Sensex, Bank Nifty, a tradable Nifty ETF
  and the Nifty 50 stocks
- significance tests with honest error bars
- a break-even cost table showing, per instrument, how many bp per round trip
  the overnight edge can pay for.

---

## Background

- The reel describes **Bruce Knuteson** (the reel spells it "Knutson"), a former
  MIT physicist who worked at D. E. Shaw. Main paper: *Strikingly Suspicious
  Overnight and Intraday Returns*, arXiv:2010.01727 (Oct 2020). It covers many
  national indices, India included.
- His explanation (the footprint of one large participant's trading) is
  contested. Other work on the same effect:
  - Cliff, Cooper & Gulen (2008), *Return differences between trading and
    non-trading hours: like night and day*.
  - Lou, Polk & Skouras (2019, JFE), *A tug of war: overnight versus intraday
    expected returns*. Explains it with investor clienteles.

## Definitions

For trading day `t`, using adjusted prices:

```
night_t = Open_t  / Close_{t-1} - 1     # close -> next open (spans weekends/holidays)
day_t   = Close_t / Open_t      - 1     # open -> close
(1 + night_t) * (1 + day_t) = Close_t / Close_{t-1}     # exact, every day
```

Chained: `N = prod(1 + night)`, `D = prod(1 + day)`, `N * D = buy-and-hold`.

Stats and plots use log returns: `log N + log D = log hold`. In log space the two
halves add and are symmetric, so the "+138M% vs -99.9%" lopsidedness the reel
explains (a loss stops at zero) goes away.

## Scope

- **Indices:** `^NSEI` (Nifty 50), `^BSESN` (Sensex), `^NSEBANK` (Bank Nifty).
- **Tradable proxy:** `NIFTYBEES.NS` (Nifty 50 ETF). You cannot buy an index,
  so the ETF's own open and close are the prices you would actually get.
- **Stocks:** current Nifty 50 constituents, `.NS` tickers. Also pick the one
  with the longest clean history for a direct Micron-style chart.
- **Dates:** each series from its first clean day (set in Phase 2) to the last
  full trading day before the run.
- **Frequency:** daily OHLC only. Free intraday history isn't available.

## Phases

### Phase 0: Scaffold
- Create a venv, then run `python -m pip install --upgrade pip` first.
- Pin every dependency to a release at least 7 days old.
- Put all tickers, dates and cost parameters in `src/config.py` and nowhere else.
- CHECKPOINT: `pip freeze`; the empty test suite runs.

### Phase 1: Acquisition
- Download with `yfinance` and `auto_adjust=True`. This adjusts Open as well as
  Close, so splits and bonus issues don't show up as fake overnight crashes.
- Cache one CSV per ticker and reuse it for the rest of the day.
- CHECKPOINT: coverage table with ticker, first/last date, row count, and days
  missing against the NSE trading calendar.

### Phase 2: Validation
Everything here depends on the Open column, which is the least reliable column
in free data.

1. **Stale opens** (Open == previous Close). These fake a zero night and push the
   whole move into the day. Pre-check on the cached `^NSEI` in
   Dynamic-Regime-Allocation (2007-09-17 .. 2026-08-13): 2-8% of days per year
   in 2007-2010, about 0% from 2011 on. That timing fits NSE's pre-open call
   auction, which started in late 2010. Treat pre-2011 opens as suspect and
   decide here whether to drop or keep them.
2. Open or Close outside [Low, High]; all four OHLC equal; zero or missing
   volume (stocks).
3. Missed corporate actions: a stock's overnight move beyond +-20% with no
   matching news is probably a split or bonus that wasn't adjusted.
4. **Non-standard sessions:**
   - Muhurat trading (the one-hour Diwali session). Its "night" and "day" mean
     something different.
   - Saturday special sessions (e.g. budget days).
   - Mock and DR-drill sessions.

   Flag them and keep them out of the main series.
5. Tag each night by calendar length: weeknight, weekend, or holiday. If the
   drift is a risk premium, longer nights should carry more of it.
6. Spot-check about 20 random days per index against NSE's official historical
   data.
- CHECKPOINT: drop table (ticker x reason x count) and the chosen start date
  per series.

### Phase 3: Decomposition
- Build the night, day and hold series per instrument. A test asserts the
  identity holds to 1e-10 on every day.
- Figures:
  - cumulative night, day and hold on a log axis, for each index and the ETF
  - small multiples for the stocks
- Summary table, one row per instrument:
  - CAGR of each leg
  - mean bp per night and per day
  - % of positive nights and days
  - volatility of each leg
- Split the nights into weeknight, weekend and holiday.
- **Dividends:** with adjusted data, a dividend shows up in the night (the
  ex-date gap). Report the night with and without ex-dates so the "night
  premium" isn't just dividends.
- CHECKPOINT: the summary table and the Nifty chart.

### Phase 4: Is it real?
Subperiods are fixed now, before any results are seen:
- 2007-2010: before the pre-open auction
- 2011-2019
- 2020 to Jun 2023: COVID and the retail surge
- Jul 2023 onward: SGX Nifty moved to GIFT City, so the Indian night is now
  priced live offshore

Tests:
- Mean night and day returns with Newey-West (HAC) t-stats.
- Stationary block bootstrap CI for (night - day).
- Cross-section across the Nifty 50 stocks: how many have night > day? Does the
  gap scale with size, liquidity, or F&O inclusion?
- Survivorship caveat: current constituents only. Today's Nifty 50 stocks are
  winners. That inflates hold but biases the night/day split less. State it and
  claim no more than that.
- CHECKPOINT: t-stat table, bootstrap CIs, subperiod table.

### Phase 5: Indian cost model
This is where the strategy lives or dies. It trades twice a day, about 250 round
trips a year, so a 0.25% round-trip cost is roughly 60% a year of drag.

Each component is a parameter in `config.py`. Check every rate against current
NSE, SEBI and broker schedules when implementing, because they change (F&O STT
changed in Oct 2024).

- **STT depends on trade type:**
  - Close -> open is a *delivery* trade (held overnight): about 0.1% on both buy
    and sell for stocks.
  - Open -> close is intraday: about 0.025%, sell side only.
  - ETF units: much lower, sell side (verify).
  - Futures: sell side only.
- **Other charges:**
  - stamp duty (buy side)
  - exchange transaction charge
  - SEBI fee
  - GST on brokerage and exchange charges
  - brokerage (zero for delivery at many discount brokers)
  - DP charge per stock per sell day. It's a flat amount, so it hits small
    accounts hardest, and brokers differ on whether BTST sells pay it.
- **Slippage:** half-spread at the open auction, plus the close mechanics
  (Phase 6).
- Output: a **break-even table** with, per instrument, the round-trip cost at
  which the night strategy's net return equals buy-and-hold, next to the
  estimated real cost.
- CHECKPOINT: break-even table.

### Phase 6: Tradable variants
- **S0** buy-and-hold (benchmark).
- **S1** long night: buy at close, sell at the next open. In India this is a
  BTST trade. Under T+1 you sell before the shares are delivered, which carries
  short-delivery/auction risk if the counterparty fails.
- **S2** short day: short at open, cover at close. Intraday cash shorting (MIS)
  is allowed, and STT is lower than for S1.
- **S3** S1 + S2 combined.
- **S4** execution-timing tilt, with no extra trades: a monthly SIP that buys at
  the close instead of the open. This measures what the pattern is worth to a
  long-term investor at zero added cost, and is probably the most practical
  takeaway.
- **S5** (optional) Nifty futures. Futures open/close data needs NSE's F&O
  bhavcopy because yfinance doesn't have it. Only worth doing if Phase 5 shows
  the ETF and stock versions die on costs and futures might not.

Execution realism:
- *Open:* NSE's opening price is set by the 09:00-09:08 pre-open call auction.
  An order can take part in it, so the open is achievable.
- *Close:* NSE's official close for stocks is the volume-weighted average of the
  last 30 minutes, not a single price you can trade at. A VWAP order over
  15:00-15:30 gets close to it. Model the leftover gap as slippage.
- CHECKPOINT: gross vs net equity curves, Sharpe ratio, max drawdown, turnover.

### Phase 7: Findings
`reports/findings.md` with the headline numbers, the chart, what survived costs,
what didn't, and the caveats.

These 5 pull in 32 transitive packages; all 37 are pinned with hashes in
`requirements.txt`. The cache is CSV, not parquet, so `pyarrow` isn't needed.
`statsmodels` was left out: Newey-West will be written in numpy in Phase 4.

**Supply-chain rules (apply to every future dependency change):**
1. Lock with `uv pip compile ... --exclude-newer <today - 7 days>`. This
   applies the cutoff to transitive dependencies too.
2. Run `python scripts/audit_deps.py --cutoff <same date>` **before**
   installing. It must print OK.
3. Install with
   `pip install --require-hashes --only-binary :all: --uploaded-prior-to <cutoff> -r requirements.txt`:
   - hash-checked
   - wheels only, so no package setup code runs at install
   - the cutoff is enforced a second time, by pip itself
4. The project is never pip-installed (no `[build-system]`). Installing it would
   fetch an unpinned build backend. pytest finds `src/` through
   `pythonpath = ["."]` instead.
